## 1. Arquitectura del Sistema

El sistema implementa una arquitectura en 2 capas privadas dentro de la VCN para garantizar máxima seguridad y soberanía de los datos:

```
[ Usuario / Helpdesk / Teams ]
             │
             ▼ (Puerto 8000 / HTTPS)
 ┌─────────────────────────────────────────────────────────────┐
 │ OCI Compute E6 (2 OCPUs, 32 GB RAM)                         │
 │                                                             │
 │  ┌────────────────────────┐    ┌─────────────────────────┐  │
 │  │ FastAPI Backend        │◄──►│ Ollama (CPU Ingestion)   │  │
 │  │ (agent.py)             │    │ Qwen 2.5 7B / Llama 3.1 │  │
 │  └───────────┬────────────┘    └─────────────────────────┘  │
 │              │ (Embeddings: multilingual-e5-base 768d en CPU)│
 └──────────────┼──────────────────────────────────────────────┘
                │ SQL Net / Puerto 1521
                ▼
 ┌─────────────────────────────────────────────────────────────┐
 │ OCI DB System (Oracle Database 26ai / 23ai)                 │
 │                                                             │
 │  • Tabla KNOWLEDGE_BASE (Columna VECTOR(768, FLOAT32))      │
 │  • Índice In-Memory HNSW (Similitud Coseno)                 │
 │  • Tabla AGENT_TICKETS_LOG (Trazabilidad y Auditoría)       │
 └─────────────────────────────────────────────────────────────┘
```

## 2. Paso 1: Configuración de Conectividad y Seguridad (VCN)

Antes de instalar software, debemos garantizar la comunicación interna entre la máquina E6 y el DBSystem:

### 2.1 Reglas de Entrada en la Security List del DBSystem
Asegurar que la Security List o Network Security Group (NSG) del DBSystem permita tráfico en el puerto Oracle Listener:
* **Protocolo:** TCP
* **Source CIDR:** CIDR de la subred de la Compute E6 (ej. `10.0.1.0/24`) o la IP privada exacta de la VM.
* **Destination Port:** `1521`
* **Descripción:** Acceso SQL Net desde backend de IA.

### 2.2 Reglas de Entrada en la Compute E6
Si el servicio del agente se consumirá desde fuera de la VM (por ejemplo, desde un API Gateway, un canal de Teams o tu máquina local):
* **Protocolo:** TCP
* **Source CIDR:** Tu red corporativa o subred del Gateway.
* **Destination Port:** `8000` (FastAPI) y `22` (SSH).

## 3. Paso 2: Inicialización en DBSystem 26ai vía SSH y SQL*Plus

Dado que el acceso al DBSystem es por SSH y SQL*Plus, conéctate al host de la base de datos:

```bash
ssh -i ~/.ssh/tu_clave_oci opc@<IP_DBSYSTEM>
```

### 2.1 Conexión con SQL*Plus y Selección de la PDB
En Oracle Database (CDB/PDB), los objetos de la aplicación deben crearse dentro de la **Pluggable Database (PDB)**, nunca en el contenedor raíz `CDB$ROOT`.

```bash
# Cambiar al usuario del motor de base de datos
sudo su - oracle

# Conectarse como SYSDBA
sqlplus / as sysdba
```

Dentro de SQL*Plus, verifica tus PDBs y cámbiate a tu PDB de trabajo:

```sql
-- Listar PDBs disponibles
SHOW PDBS;

-- Cambiar de sesión a tu PDB (ej. TU_PDB o PDB1)
ALTER SESSION SET CONTAINER = TU_PDB;

-- Verificar sesión actual
SHOW CON_NAME;
```

### 2.2 Creación de Usuario de Aplicación y Estructuras Vectoriales
Crea un usuario dedicado con cuotas y permisos:

```sql
-- Crear usuario dedicado en la PDB
CREATE USER app_support IDENTIFIED BY "TuPasswordSeguro123!"
DEFAULT TABLESPACE users
TEMPORARY TABLESPACE temp
QUOTA UNLIMITED ON users;

GRANT CONNECT, RESOURCE, CREATE TABLE, CREATE VIEW TO app_support;
-- Nota: En Oracle 23ai/26ai el tipo VECTOR y las funciones SQL como VECTOR_DISTANCE
-- son tipos escalares nativos concedidos por defecto a PUBLIC (no requieren grant de paquetes).

-- Conectarse con el usuario de aplicación en la PDB
CONNECT app_support/"TuPasswordSeguro123!"@localhost:1521/TU_PDB;


-- 1. Tabla de Conocimiento Vectorial
CREATE TABLE knowledge_base (
    id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR2(255) NOT NULL,
    category VARCHAR2(100),
    content CLOB NOT NULL,
    metadata JSON,
    embedding VECTOR(768, FLOAT32),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 2. Índice Vectorial HNSW optimizado para distancia Coseno (Enterprise Edition / ATP)
-- Nota: Requiere 'vector_memory_size' > 0 configurado en el servidor (Enterprise Edition o Autonomous ATP).
-- En Oracle Database Standard Edition 2, este índice se omite y el motor ejecuta Exact Vector Search (SIMD nativo) con 100% de precisión.
CREATE VECTOR INDEX idx_knowledge_embedding 
ON knowledge_base (embedding)
ORGANIZATION INMEMORY NEIGHBOR GRAPH
DISTANCE COSINE;

-- 3. Tabla de Logs y Auditoría de Tickets
CREATE TABLE agent_tickets_log (
    id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    ticket_external_id VARCHAR2(100),
    user_query CLOB NOT NULL,
    retrieved_context CLOB,
    agent_response CLOB,
    confidence_score NUMBER(5, 4),
    status VARCHAR2(50) DEFAULT 'auto_resolved',
    execution_time_ms NUMBER(10),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

COMMIT;

EXIT;
```

## 4. Paso 3: Configuración de la Instancia Compute E6 (Oracle Linux 10 & Ollama)

Conéctate por SSH a la instancia `VM.Standard.E6.Flex`:

```bash
ssh -i ~/.ssh/tu_clave_oci opc@<IP_COMPUTE_E6>
```

### 4.1 Actualización del Sistema en Oracle Linux 10
```bash
sudo dnf update -y
sudo dnf install -y python3 python3-pip git curl htop

# Crear entorno virtual de Python:
python3 -m venv ~/rag-env
source ~/rag-env/bin/activate
pip install --upgrade pip
```


### 4.2 Instalación de Ollama (Motor de Inferencia en CPU)
Ollama detecta automáticamente la arquitectura de la CPU E6 (AMD EPYC) y optimiza las instrucciones AVX-512:

```bash
# Instalación limpia en 1 línea
curl -fsSL https://ollama.com/install.sh | sh

# Verificar que el servicio esté activo
sudo systemctl status ollama
```

### 4.3 Descarga del Modelo LLM Cuantizado
Descargaremos **Qwen 2.5 7B** (altamente calificado para instrucciones en español y razonamiento):

```bash
ollama pull qwen2.5:7b-instruct-q4_K_M
```

> **Verificación de Consumo en CPU E6:**
> * El modelo descargado ocupa **~4.7 GB de RAM**.
> * Con los **32 GB de RAM** de la máquina E6, sobra más del 70% de memoria para caché del sistema operativo y embeddings concurrentes.
> * Puedes hacer una prueba rápida en consola:
>   ```bash
>   ollama run qwen2.5:7b-instruct-q4_K_M "Hola, preséntate brevemente como agente de soporte."
>   ```

## 5. Paso 4: Despliegue del Backend del Agente (FastAPI + oracledb)

En la máquina Compute E6:

### 5.1 Estructura de Directorios del Proyecto
```bash
mkdir -p ~/agente_soporte_rag
cd ~/agente_soporte_rag
```

Copia o transfiere a este directorio los archivos del proyecto:
* `requirements.txt`
* `ingest.py`
* `agent.py`

### 5.2 Instalación de Librerías Python a Nivel de Sistema (Optimizado para CPU)
Para no saturar el disco con drivers de NVIDIA CUDA innecesarios (que pesan más de 4 GB), instalamos primero la versión ligera de PyTorch para CPU (~180 MB) y luego el resto de dependencias:

```bash
# 1. Limpiar caché previa de pip si hubo fallo de espacio
pip3 cache purge

# 2. Instalar PyTorch compilado exclusivamente para CPU
pip3 install --break-system-packages torch --index-url https://download.pytorch.org/whl/cpu

# 3. Instalar librerías del backend y embeddings
pip3 install --break-system-packages fastapi uvicorn pydantic oracledb sentence-transformers requests python-dotenv
```

### 5.3 Variables de Entorno de Conexión (`.env`)
Crea un archivo `.env` con las credenciales de tu DBSystem:

```bash
cat << 'EOF' > .env
DB_USER=app_support
DB_PASSWORD=TuPasswordSeguro123!
DB_DSN=dbhost.sub.yourvcn.oraclevcn.com:1521/pdb1.sub.yourvcn.oraclevcn.com
OLLAMA_URL=http://localhost:11434/api/generate
OLLAMA_MODEL=qwen2.5:3b
EOF
```

## 6. Paso 5: Puesta en Marcha y Pruebas del Agente

### 6.1 Abrir el Puerto en el Firewall del SO (Oracle Linux)
Oracle Linux incluye `firewalld` activo por defecto. Para permitir el tráfico en el puerto 8000:

```bash
sudo firewall-cmd --permanent --add-port=8000/tcp
sudo firewall-cmd --reload
```

### 6.2 Ejecutar el Agente
```bash
python agent.py
```

### 6.3 Demostración de Impacto: Prueba "Antes vs. Después" de Vectorizar
Para demostrar ante clientes y en repositorios públicos que el LLM responde estrictamente gracias a los documentos indexados en Oracle 26ai:

#### Escenario 1: Pregunta ANTES de Ingestar los PDFs
Realizamos una consulta sobre una política específica corporativa que NO está en la base de datos (por ejemplo, el procedimiento de guardias o renovación de hardware):

```bash
curl -X POST http://localhost:8000/api/v1/support/resolve \
  -H "Content-Type: application/json" \
  -d '{
    "ticket_id": "TEST-BEFORE",
    "user_query": "¿Cuál es la línea y el código PIN de emergencia para activar la guardia de soporte crítico en incidentes P1 fuera de horario?"
  }'
```

*Comportamiento Obtenido:*
Como el umbral de similitud vectorial en Oracle 26ai es `< 0.35`, el agente no alucina y responde de manera segura y controlada:
```json
{
  "ticket_id": "TEST-BEFORE",
  "suggested_resolution": "No se encontró documentación suficiente en la base de conocimiento para resolver este ticket automáticamente. Se escala a un agente humano de soporte.",
  "confidence_score": 0.2104,
  "sources": []
}
```

## 7. Registro de Incidentes y Lecciones Aprendidas (Troubleshooting Log)
*(Esta sección se irá completando a medida que ejecutemos las pruebas en el entorno real)*

| Fecha | Incidencia / Desafío | Causa Raíz | Solución Aplicada |
| :--- | :--- | :--- | :--- |
| **2026-10-15** | `ORA-04042: DBMS_VECTOR does not exist` al ejecutar GRANT | En Oracle 23ai/26ai el tipo `VECTOR` y funciones SQL (`VECTOR_DISTANCE`) son tipos escalares nativos públicos del motor, no requieren paquetes PL/SQL adicionales. | Omitir el comando `GRANT EXECUTE ON DBMS_VECTOR`. Los permisos estándar `CONNECT, RESOURCE, CREATE TABLE` son suficientes. |
| **2026-10-15** | Rechazo de formato de contraseña (`ORA-28003`) al crear usuario | Función de verificación de complejidad de contraseñas de Oracle Database activa en el perfil. | Se ajustó la contraseña a `#SoporteIA2026.` (iniciando con símbolo especial y terminando con punto, cumpliendo longitud y diversidad de caracteres). |
| **2026-10-15** | Listener de Oracle no iniciado en DBSystem (`dbhost`) | Proceso listener detenido o servicio `PDB1` pendiente de registro en `tnsnames.ora`. | Iniciar listener con `lsnrctl start`, verificar servicios con `lsnrctl status` y agregar entrada TNS para `PDB1` apuntando al host `dbhost`. |
| **2026-10-15** | DBSystem aprovisionado en versión 19.32 en lugar de 23ai | Selección de versión base 19c en el aprovisionamiento inicial. | Se inició el proceso de actualización (Upgrade/Patching) a Oracle Database 23ai directamente desde la consola de OCI. |
| **2026-10-15** | `bash: pip3: command not found` en Compute E6 (Oracle Linux 10) | Imagen mínima del sistema operativo sin el gestor de paquetes de Python preinstalado. | Ejecutar `dnf install -y python3-pip` antes de instalar dependencias de la aplicación. |
| **2026-10-15** | `OSError: [Errno 28] No space left on device` al instalar `sentence-transformers` | Por defecto, `pip` descargó PyTorch con paquetes pesados de NVIDIA CUDA 12/13 (>4 GB), saturando el disco raíz en una VM de solo CPU. | Limpiar caché (`pip3 cache purge`) e instalar PyTorch ligero para CPU (`--index-url https://download.pytorch.org/whl/cpu`, ~180 MB) antes de instalar `sentence-transformers`. |
| **2026-10-15** | Partición raíz no expandida tras redimensionar Boot Volume en OCI | La tabla de particiones o el volumen lógico LVM no se expanden automáticamente sin intervención. | Usar `oci-growfs -y` o el flujo manual: `growpart`, `pvresize`, `lvextend -l +100%FREE` y `xfs_growfs /` (o `resize2fs`). |
| **2026-10-15** | `ORA-00406: COMPATIBLE parameter needs to be 20.0 or greater` al crear tabla VECTOR | Tras el upgrade de 19c a 23ai, el parámetro `COMPATIBLE` se mantiene en 19.0.0 para permitir rollback. Funcionalidades de 23ai como `VECTOR` requieren 23.0.0. | En `CDB$ROOT`: `ALTER SYSTEM SET COMPATIBLE='23.0.0' SCOPE=SPFILE;`, reiniciar la base de datos (`SHUTDOWN IMMEDIATE; STARTUP;`) y abrir las PDBs (`ALTER PLUGGABLE DATABASE ALL OPEN;`). |
| **2026-10-15** | `ORA-51962: The vector memory area is out of space for the current container` al crear índice HNSW | El pool de memoria SGA para búsqueda vectorial (`VECTOR_MEMORY_SIZE`) está en 0 por defecto tras el upgrade. Índices `INMEMORY NEIGHBOR GRAPH` requieren reservar este pool. | Configurar `ALTER SYSTEM SET VECTOR_MEMORY_SIZE=1G SCOPE=SPFILE;` en `CDB$ROOT` y reiniciar instancia. |
| **2026-10-15** | `ORA-02000: missing PARTITIONS keyword` al intentar `ORGANIZATION NEIGHBOR GRAPH` | La sintaxis oficial de Oracle 23ai para grafos HNSW exige la palabra reservada `INMEMORY` (`ORGANIZATION INMEMORY NEIGHBOR GRAPH`). Para índices sin memoria se usa IVF (`ORGANIZATION INVERTED FLAT`). Para bases de conocimiento pequeñas/medianas no se requiere índice (Exact Vector Search nativo). | Usar Exact Search (sin índice, velocidad sub-milisegundo con SIMD) o configurar `VECTOR_MEMORY_SIZE=1G` para índice HNSW. |
| **2026-10-15** | `DPY-6001: Service "PDB1" is not registered with the listener` (ORA-12514) al conectar desde Python | En OCI DB Systems el nombre del servicio de la PDB suele llevar el sufijo de dominio de la VCN (ej. `pdb1.sub.yourvcn...`) o la PDB no estaba abierta en READ WRITE tras reiniciar. | Abrir la PDB (`ALTER PLUGGABLE DATABASE PDB1 OPEN;`), registrar el servicio con `ALTER SYSTEM REGISTER;` y validar el nombre exacto con `lsnrctl status`. |
| **2026-10-15** | `DPY-3001: Native Network Encryption and Data Integrity is only supported in python-oracledb thick mode` | En OCI DB Systems `sqlnet.ora` tiene configurado por defecto `SQLNET.ENCRYPTION_SERVER = REQUIRED`. El modo *Thin* de python-oracledb no soporta NNE heredado (requiere Thick mode o TLS). Los comandos automatizados como `sed -i` pueden fallar por espaciado o formato interno. | En el DBSystem, editar manualmente (`sudo vi /opt/oracle/dcs/commonstore/wallets/tde/...` o `$ORACLE_HOME/network/admin/sqlnet.ora`) y cambiar a `SQLNET.ENCRYPTION_SERVER = ACCEPTED` y `SQLNET.CRYPTO_CHECKSUM_SERVER = ACCEPTED`. Esto habilita conexiones seguras en modo *Thin* a través de la red privada VCN sin requerir cliente Thick. |
| **2026-10-15** | Conexión entrante rechazada o timeout en puerto 8000 del backend FastAPI | La imagen oficial de Oracle Linux incluye el cortafuegos del sistema operativo (`firewalld`) activo por defecto, bloqueando puertos de servicios no estándar. | Ejecutar `firewall-cmd --add-port=8000/tcp --permanent` seguido de `firewall-cmd --reload` en la instancia Compute E6. (Adicionalmente, si se accede desde fuera de la VCN, verificar la Security List o NSG de OCI). |
